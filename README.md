# MLP — پنل مولتی‌لوکیشن روی Railway

پنل مدیریت اشتراک چندلوکیشنی: **یک پنل مرکزی + هر تعداد لوکیشن** (سرویس‌های Railway در ریجن‌های مختلف، ورکر Cloudflare و حتی VPS خودت)، همه با یک لینک اشتراک واحد که داخلش کانفیگِ همه‌ی لوکیشن‌ها با فلگ می‌آید.

<p align="center">
🇩🇪 Germany · 🇳🇱 Netherlands · 🇺🇸 United States · 🇸🇬 Singapore · ☁️ Cloudflare
</p>

## چرا این معماری؟

| | مزیت |
|---|---|
| **یک پورت برای همه‌چیز** | Railway فقط یک دامنه/پورت به هر سرویس می‌دهد؛ این پروژه کل رله را روی همان پورت اجرا می‌کند. |
| **نودها «پول» می‌کنند** | هر نود با توکن خودش به پنل وصل می‌شود (`/api/node/sync`)، پس نه پورت عمومی دوم لازم است و نه شبکه‌ی خصوصی. |
| **نود بدون پنل هم کار می‌کند** | باندل کاربران کش می‌شود؛ اگر پنل چند دقیقه قطع شود، سرویس مشتری قطع نمی‌شود. |
| **همه‌ی محدودیت‌ها روی نود اعمال می‌شود** | حجم، انقضا، حداکثر IP هم‌زمان و محدودیت سرعت — سمت نود، بدون نیاز به Xray. |
| **فلگ و لوکیشن واقعی** | هر لوکیشن خروجی/آی‌پی خودش را دارد؛ در ساب با نام و فلگ خودش می‌آید. |

## ⚡️ دو کلیک تا بالا آمدن (پورت‌ها و چیزهایی که باید ست کنی)

**پورت پنل: `8080`.** سرویس پنل به `PORT` گوش می‌دهد و اگر نبود، خودکار روی **8080** بالا می‌آید؛ پس در Railway →
Settings → Networking فقط دامنه بگیر (Railway خودش همین پورت را به دامنه وصل می‌کند). هر **نود** هم روی همان `8080`
گوش می‌دهد و به دامنه‌ی خودش وصل می‌شود.

| چه چیزی | لازم است؟ | مقدار |
|---|---|---|
| `MLP_ADMIN_PASSWORD` (سرویس پنل) | ✅ اجباری (برای امنیت) | یک رمز قوی — پیش‌فرض `admin` |
| **Volume روی `/data`** (سرویس پنل) | ✅ اجباری | وگرنه با هر دیپلوی همه‌چیز پاک می‌شود |
| `PORT` | ➖ اختیاری | پنل/نود: `8080` (پیش‌فرض امن) |
| `MLP_PUBLIC_URL` | ➖ اختیاری | اگر دامنه‌ی اختصاصی داری |
| `MLP_DATA_DIR=/data` | ➖ اختیاری | همان مسیر Volume |
| `MLP_NODE_TOKEN` (سرویس نود) | ✅ اجباری | از پنل → تب لوکیشن‌ها → «متغیرهای نود» |
| `MLP_PANEL_URL` (سرویس نود) | ✅ اجباری | دامنه‌ی پنل (با `https://`) |

**یا فقط یک توکن Railway بده:** پنل → تب **«راه‌اندازی خودکار»** → توکن حساب Railway را بچسبان → «همه‌چیز را بساز».
پنل خودش پروژه، سرویس پنل + Volume، دامنه، سرویس‌های نود در ریجن‌های انتخابی، متغیرها و ثبت لوکیشن‌ها را انجام
می‌دهد و در پایان **آدرس پنل + یوزر/پسورد ادمین** را نشان می‌دهد. (توکن از `Account → Tokens`؛ فقط ذخیره می‌شود تا هر
وقت خواستی از Railway پاکش کنی.)

## تازه‌ها (نسخه‌ی ۱.۱)

- 🎭 **سایت پوششی (Camouflage)**: پنل و هر نود برای بازدیدکننده‌ی ناشناس یک **سایت واقعی فارسی** نشان می‌دهند (فروشگاه / شرکت / وبلاگ) — نه پنل، نه خطا، نه اثری از پروکسی. پنل هم روی یک **مسیر مخفی تصادفی** بالا می‌آید.
- 🚀 **موتور Xray-core (اختیاری)**: برای سرعت و سازگاری بیشتر؛ با `MLP_ENGINE=xray` و `Dockerfile.xray` (nginx داخلی + Xray + کنترل‌پلین). بدون باینری، خودکار به موتور پایتون برمی‌گردد.
- ⚡ **بهینه‌سازی سرعت**: بافر خواندن بزرگ‌تر، `SO_SNDBUF/SO_RCVBUF`، `TCP_NODELAY` و **درین تطبیقی (AIMD)** که آستانه‌ی بافر را با سرعت واقعی مسیر تنظیم می‌کند.
- 🤝 **رزیلر + کیف پول**: رزیلر وارد ربات می‌شود، از موجودی کیف پولش کاربر می‌سازد؛ ادمین شارژ/تراکنش‌ها را تأیید می‌کند. قیمت هر GB/روز قابل تنظیم است.
- 🎨 **برند اختصاصی**: نام، شعار، لوگو، رنگ‌ها، تیتر، ویژگی‌ها، شماره کارت و مسیر مخفی پنل — همه از داخل پنل (تب «برند و ظاهر»).
- 🌐 **سایت عمومی آماده**: خانه، تعرفه‌ها، وضعیت سرویس، راهنمای اتصال، تماس، اعلان‌ها، `robots.txt` و `sitemap.xml` + حالت «به‌زودی برمی‌گردیم».
- 🎓 **آموزش راه‌اندازی داخل پنل**: ۹ گام فارسی (راه‌اندازی خودکار → فورک → پنل → لوکیشن → موتور → دامنه‌ی اختصاصی → ربات → پروکسی/تانل → تست) + دانلود فایل‌های لازم + امکان ویرایش متن هر گام.
- 🚀 **راه‌اندازی خودکار با یک توکن Railway**: ساخت پروژه/سرویس/Volume/دامنه/لوکیشن‌ها بدون کار دستی.
- 🌐 **IP و موقعیت هر لوکیشن**: پنل از خود نود می‌پرسد و **IP خروجی + کشور + شهر + فلگ + ISP** را نشان می‌دهد (دکمه‌ی «IP من») و می‌تواند فلگ لوکیشن را خودکار ست کند.
- 🧹 **IP تمیز برای هر لوکیشن**: اسکنر داخلی، آی‌پی‌های کاندید را تست می‌کند و سریع‌ترین را در کانفیگ مشتری می‌گذارد (کلاینت به IP وصل می‌شود، SNI همان دامنه می‌ماند).
- 📦 **کانفیگ جدا برای هر لوکیشن**: در ساب و صفحه‌ی مشتری، گروه‌بندی لوکیشن‌به‌لوکیشن با نامی شامل **فلگ + نام + شماره** (`{flag} {name} #1 | {panel}`).
- 🛡 **ضدِ بن و ضدِ سوءاستفاده**: بلاک پورت‌های پرخطر، محدودسازی نرخ اتصال هر IP، بَنِ خودکار اسکنرها، صفحه‌ی `/abuse` (قوانین + گزارش سوءاستفاده) و `robots.txt` محدود.
- 🔐 **امنیت**: محدودسازی تلاش ورود، محدودسازی نرخ روی خود پنل، پاسخ بی‌اثر `/healthz` بدون کلید، `noindex` روی پنل.

## امکانات

- 🛰 **لوکیشن‌ها**: افزودن/ویرایش/حذف، توکن اختصاصی، وضعیت زنده (CPU/RAM/کاربران آنلاین)، چرخش توکن
- 👥 **کاربران**: حجم، تاریخ انقضا، حداکثر IP هم‌زمان، محدودیت سرعت (kbps)، فعال/غیرفعال، صفر کردن مصرف
- 🔗 **لینک اشتراک واحد**: `https://PANEL/sub/<token>` → برای کلاینت‌ها base64 و برای مرورگر یک صفحه‌ی فارسی (حجم، انقضا، QR، کانفیگ هر لوکیشن)
- 🧾 **ربات تلگرام**: پلن‌ها، خرید، ارسال رسید، تأیید/رد توسط ادمین و تحویل خودکار لینک + دستورات ادمین
- 🛍 **پلن‌های فروش** و مدیریت سفارش‌ها
- 📈 **آمار**: ترافیک ساعتی، مصرف هر کاربر، رویدادها
- 🚦 **ترابردها**: VLESS روی **WS**، **XHTTP** (stream-up/packet-up) و **TCP** (برای نودهای VPS یا TCP Proxy ریلوی)
- ☁️ **ورکر Cloudflare** به‌عنوان یک لوکیشن مستقل (همان API نود را صدا می‌زند)
- 📱 **بدون Xray/nginx**: کل رله پایتون است؛ نصب و دیپلوی ساده
- 🤝 **رزیلرها و کیف پول**: فروش عمده به نمایندگان از داخل ربات و پنل
- 🎭 **سایت پوششی + مسیر مخفی پنل**: سرویس‌ها شبیه یک وب‌سایت معمولی به‌نظر می‌رسند

## ساختار پروژه

```text
panel/     پنل مرکزی (FastAPI + SQLite)  → روی Railway با Volume
node/      سرویس نود (رله‌ی VLESS)        → هر لوکیشن یک سرویس
worker/    ورکر Cloudflare                → لوکیشن ابری (اختیاری)
tools/     تست سرتاسری محلی
docs/      مستندات فارسی
```

## شروع سریع

0. **خودکار (توصیه‌شده)**: پنل → تب «راه‌اندازی خودکار» → توکن Railway → «همه‌چیز را بساز». با این کار مراحل ۱ تا ۳ خودکار انجام می‌شود.
1. **پنل**: در Railway یک سرویس از همین ریپو بساز، Root Directory را `panel` بگذار و یک Volume روی `/data` وصل کن.
2. **لوکیشن اول**: یک سرویس دیگر از همین ریپو با Root Directory `node` بساز (ریجن دلخواه)، دامنه بگیر.
3. در پنل → تب «لوکیشن‌ها» → «لوکیشن جدید» (نام، فلگ، دامنه‌ی نود را بگذار) → دکمه‌ی «متغیرهای نود» را بزن و همان‌ها را در Variables سرویس نود بگذار → Deploy.
4. در پنل → «کاربران» → کاربر بساز → «لینک‌ها» → لینک ساب را به مشتری بده.

راهنمای کامل با همه‌ی جزئیات: **[docs/DEPLOY-FA.md](docs/DEPLOY-FA.md)**

تست محلی:

```bash
pip install -r panel/requirements.txt
python3 tools/e2e_test.py     # پنل + نود + کلاینت واقعی VLESS
```

## مانیتور + سرعت، بدون اذیت‌شدن

- **بدون نصب چیزی روی نود**: همه‌ی محدودیت‌ها (حجم/انقضا/IP/سرعت) در خود نود و بدون Xray هم اعمال می‌شوند.
- **سرعت**: `uvloop` + بافر خواندن بزرگ‌تر + `TCP_NODELAY` + درین تطبیقی؛ Xray اختیاری برای سازگاری حداکثری.
- **هیچ ابزار اضافه‌ای سر راه ترافیک نیست**: اسکنر و پروب فقط با دستور خودت اجرا می‌شوند و در مسیر عادی هیچ هزینه‌ای ندارند.
- **ضدِ بن سرویس**: پورت‌های پرخطر بسته، نرخ اتصال هر IP محدود، اسکنرها بَن می‌شوند و صفحه‌ی `/abuse` برای پاسخ به شکایت‌ها آماده است.

## امنیت

- رمز ادمین با PBKDF2 ذخیره می‌شود؛ سشن‌ها کوکی `HttpOnly` با انقضای ۷ روز.
- توکن هر نود فقط به همان داده‌ی لوکیشن دسترسی دارد (لیست کاربران + گزارش مصرف) و به حساب‌ها/تنظیمات/ربات راه ندارد.
- ترافیک مشتری روی TLS خود Railway (یا Cloudflare) می‌نشیند؛ مقصد از داخل نود باز می‌شود.
- همه‌ی محدودیت‌ها روی نودenforce می‌شوند، پس حتی اگر کسی به لینک ساب دسترسی پیدا کند، بدون احراز UUID چیزی عبور نمی‌کند.

## همه‌ی لوکیشن‌ها: مستقیم، پروکسی IP یا تانل 🌐

هر لوکیشن یک **مسیر خروج** دارد و از داخل پنل (فرم لوکیشن → «مسیر خروج») **زنده** تغییر می‌کند:

| حالت | معنی |
|---|---|
| `direct` | خود نود خروجی است |
| `proxy` | از **پروکسی IP** (SOCKS5 / SOCKS5h / HTTP CONNECT، تک یا چندتایی با انتخاب سریع‌ترین) |
| `chain` | **تانل/چین** به یک سرور VLESS دیگر (نود دوم، ورکر Cloudflare، هر سرور VLESS) |
| `auto` | اول خروجی تنظیم‌شده و در خرابی، مسیر سالم بعدی (fallback) |

- چند لوکیشن با IP متفاوت، فقط با **یک** سرور (هر لوکیشن یک پروکسی IP).
- ورکر Cloudflare هم `PROXYIP` و هم `CHAIN_URL` را پشتیبانی می‌کند؛ برعکسش، نود خودت با
  `MLP_TCP_PORT` می‌تواند **ProxyIP** ورکر باشد و ترابرد **TCP خام** را هم سرو کند.
- هر مسیر آمار دارد (تأخیر EWMA، موفق/ناموفق، خنک‌سازی بعد از خطا) و دکمه‌ی «تست خروج» در پنل.

راهنمای کامل با سناریوها: **[docs/EGRESS-FA.md](docs/EGRESS-FA.md)**

## تفاوت موتور پایتون و Xray

| | موتور پایتون (پیش‌فرض) | موتور Xray |
|---|---|---|
| راه‌اندازی | همان Dockerfile فعلی | `node/Dockerfile.xray` + `MLP_ENGINE=xray` |
| حجم و انقضا | ✅ روی نود | ✅ از API آماری Xray |
| محدودیت سرعت (kbps) | ✅ | ❌ (Xray پشتیبانی نمی‌کند) |
| حداکثر IP هم‌زمان | ✅ | ❌ |
| سرعت/سازگاری | خوب | بهتر (چند کاربر هم‌زمان، پایتون درگیر نیست) |
| سایت پوششی | ✅ (FastAPI) | ✅ (nginx → کنترل‌پلین سبک) |
