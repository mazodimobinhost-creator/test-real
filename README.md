# MLP — پنل مولتی‌لوکیشن روی Railway

پنل مدیریت اشتراک چندلوکیشنی: **یک پنل مرکزی + هر تعداد لوکیشن** (سرویس‌های Railway در ریجن‌های مختلف، ورکر Cloudflare و حتی VPS خودت)، همه با یک لینک اشتراک واحد که داخلش کانفیگِ همه‌ی لوکیشن‌ها با فلگ می‌آید.

🇩🇪 Germany · 🇳🇱 Netherlands · 🇺🇸 United States · 🇸🇬 Singapore · ☁️ Cloudflare
</p>

## چرا این معماری؟

| | مزیت |
|---|---|
| **یک پورت برای همه‌چیز** | Railway فقط یک دامنه/پورت به هر سرویس می‌دهد؛ این پروژه کل رله را روی همان پورت اجرا می‌کند. |
| **نودها «پول» می‌کنند** | هر نود با توکن خودش به پنل وصل می‌شود (`/api/node/sync`)، پس نه پورت عمومی دوم لازم است و نه شبکه‌ی خصوصی. |
| **نود بدون پنل هم کار می‌کند** | باندل کاربران کش می‌شود؛ اگر پنل چند دقیقه قطع شود، سرویس مشتری قطع نمی‌شود. |
| **همه‌ی محدودیت‌ها روی نود اعمال می‌شود** | حجم، انقضا، حداکثر IP هم‌زمان و محدودیت سرعت — سمت نود، بدون نیاز به Xray. |
| **فلگ و لوکیشن واقعی** | هر لوکیشن خروجی/آی‌پی خودش را دارد؛ در ساب با نام و فلگ خودش می‌آید. |

## امکانات

- 🛰 **لوکیشن‌ها**: افزودن/ویرایش/حذف، توکن اختصاصی، وضعیت زنده (CPU/RAM/کاربران آنلاین)، چرخش توکن
- 👥 **کاربران**: حجم، تاریخ انقضا، حداکثر IP هم‌زمان، محدودیت سرعت (kbps)، فعال/غیرفعال، صفر کردن مصرف
- 🔗 **لینک اشتراک واحد**: `https://PANEL/sub/<token>` → برای کلاینت‌ها base64 و برای مرورگر یک صفحه‌ی فارسی (حجم، انقضا، QR، کانفیگ هر لوکیشن)
- 🧾 **ربات تلگرام**: پلن‌ها، خرید، ارسال رسید، تأیید/رد توسط ادمین و تحویل خودکار لینک + دستورات ادمین
- 🛍 **پلن‌های فروش** و مدیریت سفارش‌ها
- 📈 **آمار**: ترافیک ساعتی، مصرف هر کاربر، رویدادها
- 🚦 **ترابردها**: VLESS روی **WS**، **XHTTP** (stream-up/packet-up) و **TCP** (برای نودهای VPS یا TCP Proxy ریلوی)
- ☁️ **ورکر Cloudflare** به‌عنوان یک لوکیشن مستقل (همان API نود را صدا می‌زند)
- 📱 **بدون Xray/nginx**: کل رله پایتون است؛ نصب و دیپلوی ساده

## ساختار پروژه

```text
panel/     پنل مرکزی (FastAPI + SQLite)  → روی Railway با Volume
node/      سرویس نود (رله‌ی VLESS)        → هر لوکیشن یک سرویس
worker/    ورکر Cloudflare                → لوکیشن ابری (اختیاری)
tools/     تست سرتاسری محلی
docs/      مستندات فارسی
```

## شروع سریع

1. **پنل**: در Railway یک سرویس از همین ریپو بساز، Root Directory را `panel` بگذار و یک Volume روی `/data` وصل کن.
2. **لوکیشن اول**: یک سرویس دیگر از همین ریپو با Root Directory `node` بساز (ریجن دلخواه)، دامنه بگیر.
3. در پنل → تب «لوکیشن‌ها» → «لوکیشن جدید» (نام، فلگ، دامنه‌ی نود را بگذار) → دکمه‌ی «متغیرهای نود» را بزن و همان‌ها را در Variables سرویس نود بگذار → Deploy.
4. در پنل → «کاربران» → کاربر بساز → «لینک‌ها» → لینک ساب را به مشتری بده.

راهنمای کامل با همه‌ی جزئیات: **[docs/DEPLOY-FA.md](docs/DEPLOY-FA.md)**

تست محلی:

```bash
pip install -r panel/requirements.txt
python3 tools/e2e_test.py     # پنل + نود + کلاینت واقعی VLESS
```

## متغیرهای مهم

| سرویس | متغیر | توضیح |
|---|---|---|
| پنل | `MLP_ADMIN_PASSWORD` | رمز اولیه‌ی ادمین (پیش‌فرض `admin` — عوضش کن) |
| پنل | `MLP_PUBLIC_URL` | دامنه‌ی عمومی پنل (اگر خودکار تشخیص داده نشد) |
| پنل | `MLP_DATA_DIR` | مسیر پایگاه‌داده (باید روی Volume باشد) |
| نود | `MLP_PANEL_URL` | دامنه‌ی پنل |
| نود | `MLP_NODE_TOKEN` | توکن لوکیشن از پنل |
| نود | `MLP_WS_PATH` / `MLP_XHTTP_PATH` | مسیرها (پیش‌فرض `/ws` و `/xhttp`) |

## امنیت

- رمز ادمین با PBKDF2 ذخیره می‌شود؛ سشن‌ها کوکی `HttpOnly` با انقضای ۷ روز.
- توکن هر نود فقط به همان داده‌ی لوکیشن دسترسی دارد (لیست کاربران + گزارش مصرف) و به حساب‌ها/تنظیمات/ربات راه ندارد.
- ترافیک مشتری روی TLS خود Railway (یا Cloudflare) می‌نشیند؛ مقصد از داخل نود باز می‌شود.
- همه‌ی محدودیت‌ها روی نودenforce می‌شوند، پس حتی اگر کسی به لینک ساب دسترسی پیدا کند، بدون احراز UUID چیزی عبور نمی‌کند.
