# راهنمای کامل راه‌اندازی و استفاده (فارسی)

این سند همه‌ی چیزی است که برای راه‌اندازی واقعی سرویس لازم داری: از صفر تا اولین مشتری.
همین راهنما به‌صورت گام‌به‌گام **داخل خود پنل** (تب «آموزش راه‌اندازی») هم هست و می‌توانی متنش را ویرایش کنی.

---

## ۰. فهرست سریع

> **میان‌بر:** اگر فقط یک **توکن Railway** بدهی، گام ۰ همه‌چیز را خودکار می‌سازد (پروژه، سرویس پنل + Volume، دامنه، سرویس‌های نود در ریجن‌های انتخابی،
> متغیرها و ثبت لوکیشن‌ها) و در پایان آدرس پنل + یوزر/پسورد را نشان می‌دهد.

| گام | کار | زمان |
|---|---|---|
| ۰ | **راه‌اندازی خودکار** (تب «راه‌اندازی خودکار» + توکن Railway) | ۳ دقیقه |
| ۱ | فورک ریپو | ۱ دقیقه |
| ۲ | سرویس **پنل** روی Railway (+ Volume روی `/data`) | ۲ دقیقه |
| ۳ | سرویس **نود** (اولین لوکیشن) | ۲ دقیقه |
| ۴ | انتخاب موتور: پایتون یا Xray | ۱ دقیقه |
| ۵ | دامنه‌ی اختصاصی برای لینک ساب (اختیاری ولی توصیه‌شده) | ۳ دقیقه |
| ۶ | ربات تلگرام و فروش خودکار | ۳ دقیقه |
| ۷ | رزیلر و کیف پول | ۲ دقیقه |
| ۸ | IP/موقعیت لوکیشن‌ها + اسکنر IP تمیز | ۲ دقیقه |
| ۹ | تست نهایی | ۲ دقیقه |

## ۰. راه‌اندازی خودکار روی Railway (توصیه‌شده) 🚀

**پورت پنل `8080` است** (سرویس به `PORT` گوش می‌دهد و در نبودش روی 8080 بالا می‌آید). حداقل چیزی که سرویس پنل برای
بالا آمدن لازم دارد: یک **Volume روی `/data`** و یک **`MLP_ADMIN_PASSWORD`** (و اگر دامنه‌ی اختصاصی داری، `MLP_PUBLIC_URL`).
سرویس نود هم فقط `MLP_PANEL_URL` و `MLP_NODE_TOKEN` می‌خواهد.

۰. در سرویس Railway → **Settings → Source** شاخه‌ای که کد داخلش است را انتخاب کن (شاخه‌ی `main` اگر خالی باشد → خطای
   `Railpack failed to prepare the build` / «The app contents that Railpack analyzed contains: README.md»).
   برای پنل **Root Directory = `panel`** و برای هر نود **Root Directory = `node`**؛ اگر Root Directory را خالی بگذاری،
   `Dockerfile` ریشه پنل را می‌سازد.
۱. در Railway → **Account → Tokens → Create Token** یک توکن بساز و کپی کن.
۲. در پنل → تب **«راه‌اندازی خودکار»** → توکن را بچسبان → **«تست توکن»** (نام حساب را نشان می‌دهد).
۳. ریپوی فورک‌شده (`username/repo`) و نام پروژه را بگذار؛ رمز ادمین را خالی بگذار تا **رمز تصادفی امن** ساخته شود.
۴. برای هر لوکیشن: نام، فلگ و **ریجن** را انتخاب کن (پیشنهاد برای ایران: `europe-west4` آمستردام یا `europe-west3` فرانکفورت).
۵. **«همه‌چیز را بساز»** را بزن؛ مراحل زنده نشان داده می‌شوند. در پایان: آدرس پنل، یوزر `admin` و پسورد.
۶. بعد از بالا آمدن پنل، در تب «لوکیشن‌ها» روی **«IP من»** بزن تا پنل IP و کشور/شهر/فلگ هر لوکیشن را نشان دهد (و
   با یک کلیک فلگ لوکیشن را ست کند). اگر خواستی برای هر لوکیشن **IP تمیز** داشته باشی، دکمه‌ی **«اسکن»** را بزن.

> اگر توکن نداری یا ساخت خودکار خطا داد، همین گام‌های ۱ تا ۹ دستی هستند و هیچ خطری ندارند.

## ۱. فورک ریپو

بالای صفحه‌ی گیت‌هاب دکمه‌ی **Fork** را بزن. بعد از آن ریپو در حساب خودت است و می‌توانی همه‌چیز را تغییر بدهی.
هیچ کلید یا رمزی داخل کد نیست؛ همه‌ی مقادیر حساس از **متغیرهای محیطی** خوانده می‌شوند.

---

## ۲. سرویس پنل

در Railway → **New Project** → **Deploy from GitHub repo** → ریپوی فورک‌شده.

| تنظیم | مقدار |
|---|---|
| Root Directory | `panel` |
| Volume | مسیر `/data` (اجباری — بدون آن با هر دیپلوی داده پاک می‌شود) |
| Networking | **Generate Domain** (پورت `8080`) |
| Builder | Dockerfile (خودکار از `panel/Dockerfile`) |

**متغیرها (Variables):**

```env
MLP_ADMIN_USER=admin
MLP_ADMIN_PASSWORD=یک-رمز-قوی
MLP_DATA_DIR=/data
MLP_PUBLIC_URL=https://<دامنه‌ی-پنل>
MLP_REPO_URL=https://github.com/<username>/<repo>   # اختیاری، برای متن آموزش
```

**مسیر مخفی پنل:** پنل روی یک مسیر تصادفی بالا می‌آید (مثلاً `https://panel.up.railway.app/1f0df667`).
آدرس آن در لاگ استارتاپ پنل چاپ می‌شود و از راه `https://panel.up.railway.app/go` هم همیشه به آن می‌رسی.
از تب «برند و ظاهر» می‌توانی مسیر را عوض کنی.

> ⚠️ رمز پیش‌فرض `admin` است. بعد از اولین ورود، از تب «تنظیمات» عوضش کن.

## ۳. اولین لوکیشن (نود)

یک سرویس **جدید** در همان پروژه بساز (همین ریپو):

| تنظیم | مقدار |
|---|---|
| Root Directory | `node` |
| Region | مثلاً `europe-west4` (آمستردام) — ثابت‌کننده‌ی کشور خروجی |
| Networking | **Generate Domain** (پورت `8080`) |

بعد در پنل → تب **«لوکیشن‌ها»** → **«لوکیشن جدید»**: نام، فلگ، دامنه‌ی نود و ترابردها را وارد کن → ذخیره.
پنل یک جعبه‌ی **«متغیرهای نود»** نشان می‌دهد؛ همان‌ها را در سرویس نود بگذار و Deploy کن:

```env
MLP_PANEL_URL=https://<دامنه‌ی-پنل>
MLP_NODE_TOKEN=mlp_...        # از خود پنل
MLP_NODE_NAME=Germany
MLP_NODE_FLAG=🇩🇪
MLP_WS_PATH=/ws
MLP_XHTTP_PATH=/xhttp
MLP_DECOY=auto                # سایت پوششی
MLP_ENGINE=python             # یا xray
```

پس از چند ثانیه کارت لوکیشن سبز (آنلاین) می‌شود و در لاگ رویدادها می‌بینی: «باندل به‌روزرسانی شد».

**هر لوکیشن جدید = تکرار همین کار** (سرویس جدید + ریجن جدید + لوکیشن جدید در پنل). همه در **یک** لینک ساب مشتری می‌آیند.

### لوکیشن روی VPS خودت

```bash
git clone https://github.com/<username>/<repo>.git mlp && cd mlp
sudo bash node/install-vps.sh          # سرویس systemd + nginx + گواهی Let's Encrypt
```

در پایان، اسکریپت دستور `MLP_NODE_TOKEN` و دامنه را چاپ می‌کند؛ همان‌ها را در پنل به‌عنوان لوکیشن جدید ثبت کن.

### لوکیشن روی Cloudflare Workers (ارزان‌ترین گزینه)

`worker/worker.js` را در Cloudflare Workers دیپلوی کن و لوکیشن را با همان توکن اضافه کن؛ همان API نود را حرف می‌زند.

## ۴. انتخاب موتور

### الف) موتور پایتون (پیش‌فرض، بدون تنظیم اضافه)

- همه‌ی محدودیت‌ها اعمال می‌شود: **حجم، انقضا، سرعت (kbps)، حداکثر IP هم‌زمان**
- هیچ باینری اضافه‌ای لازم نیست؛ همان `node/Dockerfile`
- مناسب اکثر کاربران تا چند صد اتصال هم‌زمان

### ب) موتور Xray-core (سرعت و سازگاری بیشتر)

1. در پنل، لوکیشن را ویرایش کن و **موتور = xray** بگذار.
2. در Railway → سرویس نود → Settings → Build → **Dockerfile Path** = `node/Dockerfile.xray`
3. متغیر `MLP_ENGINE=xray` را ست کن و Deploy کن.

معماری داخل کانتینر:

```text
PORT (تنها پورت عمومی)
 ├── /ws           → Xray  (127.0.0.1:18080)   VLESS+WS
 ├── /xhttp        → Xray  (127.0.0.1:18081)   VLESS+XHTTP
 └── / و بقیه      → FastAPI (127.0.0.1:8090)  سایت پوششی + کنترل‌پلین
```

- مصرف از **API آماری** Xray خوانده می‌شود (`xray api statsquery`).
- کاربران به‌صورت زنده اضافه/حذف می‌شوند (`AddUser`/`RemoveUser`) — بدون ری‌استارت.
- **محدودیت سرعت و حداکثر IP در حالت Xray اعمال نمی‌شود** (Xray چنین چیزی ندارد). اگر این دو برایت مهم است، روی موتور پایتون بمان.
- اگر باینری Xray پیدا نشود، نود خودکار و بدون قطعی روی موتور پایتون می‌رود (`/healthz?key=<token>` وضعیت را نشان می‌دهد).

## ۵. سایت پوششی (Camouflage) 🎭

هر بازدیدکننده‌ی ناشناس — برای پنل و برای نود — یک **سایت واقعی فارسی** می‌بیند:

| متغیر | نتیجه |
|---|---|
| `MLP_DECOY=auto` | انتخاب پایدار بر اساس نام/دامنه‌ی سرویس (با هر ری‌استارت عوض نمی‌شود) |
| `MLP_DECOY=shop` | فروشگاه اینترنتی با محصولات و سبد خرید |
| `MLP_DECOY=corp` | سایت شرکتی با خدمات و درباره ما |
| `MLP_DECOY=blog` | وبلاگ با نوشته‌ها |
| `MLP_DECOY=none` | خاموش (پاسخ `204` خالی) |

- صفحات: خانه، محصولات/خدمات/نوشته‌ها، درباره ما، تماس، ۴۰۴ — همه با ناوبری و فوتر واقعی.
- نام برند سایت با `MLP_DECOY_NAME` عوض می‌شود.
- مسیرهای پروکسی (`/ws`, `/xhttp`) دست‌نخورده می‌مانند؛ فقط مسیرهای دیگر به سایت می‌رسند.
- بازدید مرورگر روی `/ws` هم به سایت پوششی منتهی می‌شود، نه خطا.

### سایت عمومی پنل

پنل هم یک سایت کامل دارد: `/` (خانه)، `/plans` (تعرفه‌ها)، `/status` (وضعیت لوکیشن‌ها)،
`/download` (راهنمای اتصال + لینک اپ‌ها)، `/contact`، `robots.txt`، `sitemap.xml`، و `/api/site` (JSON عمومی).
سه حالت دارد (تب «برند و ظاهر»): **سایت کامل**، **بدون سایت (فقط پنل)** و **«به‌زودی برمی‌گردیم»**.

## ۶. دامنه‌ی اختصاصی برای لینک ساب 🌐

**راه اول — Cloudflare (توصیه‌شده):**

1. دامنه را به Cloudflare اضافه کن (رکوردهای DNS دلخواه، Proxied).
2. رکورد `CNAME`: `sub` → دامنه‌ی پنل (`...up.railway.app`) و ابر نارنجی **روشن**.
3. SSL/TLS → Edge Certificates → Always Use HTTPS: روشن (اگر روی مسیر ساب باز شد، صفحه‌ی HTML می‌بینی).
4. در پنل → «برند و ظاهر» → **دامنه‌ی عمومی** = `https://sub.example.com` → ذخیره.

**راه دوم — دامنه‌ی اختصاصی Railway:** Settings → Networking → **Custom Domain** و رکورد CNAME پیشنهادی.

از این لحظه لینک‌ها این‌شکل می‌شوند:

```
https://sub.example.com/sub/<token>          ← لینک ساب (base64 برای کلاینت، HTML برای مرورگر)
https://sub.example.com/sub/<token>?stats=1  ← اطلاعات JSON (برای ربات/سایت)
https://sub.example.com/sub/<token>?format=plain
```

## ۷. ربات تلگرام و فروش خودکار

1. از [@BotFather](https://t.me/BotFather) توکن بگیر.
2. در پنل → تب «تنظیمات»: توکن، **آیدی عددی ادمین‌ها** (با کاما)، کانال اجباری (اختیاری) → ذخیره و «تست ربات».
3. در تب «پلن‌ها» تعرفه‌ها را بساز (نام، حجم، مدت، قیمت مشتری، قیمت رزیلر).
4. شماره کارت و نام دارنده را در تب «برند و ظاهر» بگذار.

جریان خرید مشتری:

```text
/start → انتخاب پلن → نمایش شماره کارت → ارسال عکس رسید
       → اعلان به ادمین → تأیید → ارسال خودکار لینک ساب به مشتری
```

دستورات:

| دستور | نقش |
|---|---|
| `/start`, `/me` | مشتری |
| `/stats`, `/nodes`, `/users` | ادمین |
| `/adduser name gb days` | ساخت سریع کاربر |
| `/resellers`, `/announce متن` | مدیریت رزیلرها و اعلان همگانی |
| `/reseller` | ورود رزیلر (نام کاربری + رمز) |
| `/myusers`, `/cancel` | رزیلر |

---

## ۸. رزیلر و کیف پول 🤝

1. پنل → تب **«رزیلرها»** → «رزیلر جدید»: نام، نام کاربری، رمز، **قیمت هر GB** و **قیمت هر روز** (تومان) و حداقل خرید.
2. برای شارژ: دکمه‌ی «شارژ» یا تأیید درخواست‌های رزیلر در تب **«کیف پول»**.
3. رزیلر در ربات `/reseller` می‌زند، وارد می‌شود و از موجودی‌اش کاربر می‌سازد یا پلن می‌خرد.
4. هر کاربری که رزیلر بسازد، در تب «کاربران» با نام رزیلر مشخص است و در آمار پنل شمرده می‌شود.

اگر پلن «قیمت رزیلر» داشته باشد همان کسر می‌شود؛ وگرنه به‌صورت خودکار
`حجم × قیمت GB + روز × قیمت روز` حساب می‌شود. کمبود موجودی = خرید انجام نمی‌شود.

## ۹. بهینه‌سازی سرعت ⚡

| کار | نتیجه |
|---|---|
| موتور Xray | رله در C/Go، پایتون فقط کنترل‌پلین |
| `MLP_READ_BUFFER` (پیش‌فرض ۱۲۸KB) | خواندن حجیم‌تر از سوکت در هر بار |
| `MLP_DRAIN_HIGH_WATER` + درین تطبیقی | آستانه‌ی بافر با سرعت مسیر بالا/پایین می‌رود (AIMD) |
| `SO_SNDBUF/SO_RCVBUF = 2MB` + `TCP_NODELAY` | بدون تأخیر Nagle و بافر هسته‌ی بزرگ‌تر |
| ریجن نزدیک به کاربر | تأخیر کمتر (Railway: انتخاب ریجن در ساخت سرویس) |
| Cloudflare Proxied روی دامنه | مسیر بهتر و مخفی‌ماندن IP |
| ترابرد XHTTP برای شبکه‌های سخت | سازگاری بالاتر با فیلترینگ |

> نکته: محدودیت سرعت کاربر (`speed_kbps`) خودش عمداً کند می‌کند؛ برای کاربر VIP آن را صفر بگذار.

**سرعت + ضدِ اذیت‌شدن:** پنل و نود پایتون را با `uvloop` اجرا می‌کنند (`requirements.txt`)، اسکنر و پروب فقط وقتی خودت
دکمه را بزنی اجرا می‌شوند و در مسیر ترافیک هیچ ابزار اضافه‌ای نیست. برای اینکه سرویس بن/شکایت نخورد:

| محافظ | مقدار پیش‌فرض | نتیجه |
|---|---|---|
| `MLP_BLOCK_PORTS` | SMTP/SMB/IRC/… | جلوگیری از اسپم و اسکن پورت |
| `MLP_MAX_CONN_PER_IP_MIN` | ۹۰ | کاربر معمولی محدود نمی‌شود، اسکنر بله |
| `MLP_PROBE_BAN_AFTER` / `MLP_BAN_SECONDS` | ۴۰ / ۶۰۰ | بَن خودکار کسی که پشت‌سرهم مسیر ناموجود می‌زند |
| محدودسازی نرخ پنل | ۲۴۰/دقیقه هر IP | جلوگیری از غرق‌کردن پنل |
| `/abuse` | صفحه‌ی قوانین + گزارش | شکایت‌ها را قبل از رسیدن به هاستر حل می‌کند |

## ۱۰. تست نهایی ✅

```bash
curl -s https://<panel>/healthz                      # {"ok":true,...}
curl -s "https://<node>/healthz?key=<token>"          # وضعیت کامل نود (اتصال به پنل، موتور)
curl -s https://<node>/                                # باید سایت پوششی را ببینی، نه خطا
```

- [ ] کارت لوکیشن‌ها در داشبورد **سبز** است
- [ ] لینک ساب در v2rayNG / Hiddify / Streisand وارد شد و همه‌ی لوکیشن‌ها آمدند
- [ ] بعد از اتصال، مصرف در پنل بالا می‌رود (تب کاربران)
- [ ] صفحه‌ی `/` پنل سایت عمومی نشان می‌دهد و مسیر مخفی پنل باز می‌شود
- [ ] ربات جواب `/start` می‌دهد

## ۱۱. عیب‌یابی

| نشانه | علت / راه‌حل |
|---|---|
| لوکیشن آفلاین می‌ماند | `MLP_PANEL_URL` یا `MLP_NODE_TOKEN` غلط است؛ لاگ نود را ببین |
| `/healthz` نود بدون کلید `{"status":"ok"}` می‌دهد | درست است! برای جزئیات `?key=<MLP_NODE_TOKEN>` بگذار |
| کلاینت وصل نمی‌شود ولی صفحه‌ی ساب باز می‌شود | مسیرها را چک کن: `MLP_WS_PATH`/`MLP_XHTTP_PATH` باید با پنل یکی باشد |
| پنل بعد از دیپلوی خالی است | Volume روی `/data` وصل نیست |
| مسیر مخفی پنل را گم کردی | لاگ استارتاپ یا `https://<panel>/go` |
| «ورود ناموفق» پشت‌سرهم و بعد قفل شدن | محدودسازی تلاش ورود (۸ بار در ۱۰ دقیقه) فعال شد؛ چند دقیقه صبر کن |
| Xray بالا نمی‌آید | Dockerfile Path را روی `node/Dockerfile.xray` بگذار و `MLP_ENGINE=xray` را ست کن؛ خودکار به پایتون برمی‌گردد |

## ۱۲. فایل‌ها و مسیرها
