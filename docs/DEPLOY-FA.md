# راهنمای نصب و راه‌اندازی (فارسی)

این راهنما گام‌به‌گام است: از صفر تا پنل بالا با چند لوکیشن.

---

## ۰) پیش‌نیازها

- یک اکانت [GitHub](https://github.com)
- یک اکانت [Railway](https://railway.com) (توجه: چند سرویس + Volume مصرف اعتبار دارد؛ پلن Free/آزمایشی هم کافی است ولی برای چند لوکیشن بهتر است Hobby داشته باشی)
- یک ربات تلگرام (اختیاری، برای فروش/مدیریت) از [@BotFather](https://t.me/BotFather)

> این ریپو را **Fork** کن تا بتوانی روی Railway دیپلوی کنی و آپدیت بگیری.

---

## ۱) سرویس پنل (مرکزی)

1. Railway → **New Project → Deploy from GitHub repo** → ریپوی Fork‌شده.
2. روی سرویس ساخته‌شده: **Settings → Source → Root Directory** را بگذار `panel`.
3. **Settings → Deploy → Config file** اگر لازم شد بگذار `panel/railway.toml`.
4. **Variables** را ست کن:

| متغیر | مقدار |
|---|---|
| `MLP_ADMIN_PASSWORD` | یک رمز قوی (به‌جای `admin`) |
| `MLP_ADMIN_USER` | نام کاربری پنل (پیش‌فرض `admin`) |
| `MLP_PUBLIC_URL` | خالی بگذار؛ اگر دامنه‌ی اختصاصی داری، مثل `https://panel.example.com` |

5. **Settings → Networking → Generate Domain** → پورت `8080` (یا همان پورت داخلی کانتینر).
6. **حیاتی**: روی سرویس راست‌کلیک → **Attach Volume** → مسیر دقیقاً `/data`
   (بدون Volume با هر دیپلوی همه‌ی کاربران و لوکیشن‌ها پاک می‌شوند.)
7. Deploy را بزن. وقتی لاگ `panel started` را دیدی، دامنه را باز کن:
   - `https://<domain>/` → صفحه‌ی ورود
   - `/healthz` → باید `{"ok":true,...}` بدهد

---

## ۲) لوکیشن اول (یک سرویس نود)

1. در **همان پروژه** Railway → **+ New → GitHub Repo** → همین ریپو (یک سرویس جدید).
2. **Root Directory** = `node`.
3. **Region** را از **Settings → Deploy** انتخاب کن (برای ایران: **EU West / Amsterdam**؛ برای پینگ آمریکا: **US East**).
4. **Generate Domain** بزن و پورت را `8080` بگذار. دامنه را جایی کپی کن.
5. هنوز Variables را ست نکن — اول توکن را از پنل می‌گیریم.

### ۲.۱) ساخت لوکیشن در پنل و گرفتن توکن

1. پنل → تب **لوکیشن‌ها** → **+ لوکیشن جدید**:
   - نام: `Germany`
   - فلگ: `🇩🇪`
   - ریجن: `europe-west4` (فقط برای یادداشت)
   - دامنه‌ی عمومی نود: همان دامنه‌ی سرویس نود (بدون `https://` هم می‌شود)
   - ترابردها: `WS` (و اگر خواستی `XHTTP`)
2. ذخیره کن؛ در پیام بازشده دکمه‌ی **کپی** را بزن (این متن، متغیرهای سرویس نود است):

```ini
MLP_ROLE=node
MLP_PANEL_URL=https://<panel-domain>
MLP_NODE_TOKEN=mlp_xxxxxxxxxxxxxxxx
MLP_NODE_NAME=Germany
MLP_NODE_FLAG=🇩🇪
MLP_WS_PATH=/ws
MLP_XHTTP_PATH=/xhttp
```

### ۲.۲) ست کردن متغیرها روی سرویس نود

روی سرویس نود → **Variables** → همه‌ی خطوط بالا را (به‌صورت جداگانه) اضافه کن → Deploy.

### ۲.۳) بررسی

- در پنل، کارت لوکیشن باید بعد از ~۳۰ ثانیه **آنلاین** شود.
- `https://<node-domain>/healthz` باید `panel_ok: true` بدهد.
- اگر آفلاین است: `https://<node-domain>/` را باز کن؛ پیام خطای اتصال به پنل را نشان می‌دهد (معمولاً توکن یا آدرس پنل اشتباه است).

---

## ۳) افزودن لوکیشن‌های بعدی

برای هر لوکیشن فقط مرحله‌ی ۲ را تکرار کن (سرویس جدید + ریجن جدید + لوکیشن جدید در پنل + متغیرها).
هر لوکیشن دامنه‌ی خودش را دارد و همه‌ی کانفیگ‌ها در **یک لینک ساب** به مشتری می‌رسد.

> نکته: ریجن را **به‌ازای هر سرویس** انتخاب می‌کنی، نه برای کل پروژه. همه‌ی سرویس‌ها می‌توانند در یک پروژه باشند.

---

## ۴) ساخت کاربر و لینک اشتراک

1. تب **کاربران** → **+ کاربر جدید**: نام، حجم (GB)، مدت (روز)، حداکثر IP، سرعت (kbps، 0=نامحدود).
2. روی **لینک‌ها** بزن:
   - **لینک ساب** = `https://<panel-domain>/sub/<token>`
   - برای کلاینت‌ها (v2rayNG/Hiddify/Streisand/…) همین لینک را وارد کن.
   - در مرورگر همین لینک یک صفحه‌ی فارسی با مصرف، انقضا، QR و کانفیگ هر لوکیشن نشان می‌دهد.
3. کانفیگ‌ها به‌صورت خودکار برای همه‌ی لوکیشن‌های فعال ساخته می‌شوند (`🇩🇪 Germany | پنل`، `🇺🇸 United States | پنل`، …).

---

## ۵) ورکر Cloudflare به‌عنوان یک لوکیشن (اختیاری)

اگر می‌خواهی یک لوکیشن «ابری» هم داشته باشی (آی‌پی‌های Cloudflare، مناسب وقتی آی‌پی Railway فیلتر است):

1. پنل → لوکیشن جدید: نام `Cloudflare`، فلگ `☁️`، دامنه‌ی عمومی = دامنه‌ای که برای ورکر می‌گیری، **لوکیشن Cloudflare** را هم همان دامنه بگذار → ذخیره → توکن را کپی کن.
2. [Cloudflare Dashboard](https://dash.cloudflare.com) → **Workers & Pages → Create Worker** → کد فایل `worker/worker.js` را جای‌گذاری کن.
3. در **Settings → Variables**:

| نام | مقدار |
|---|---|
| `PANEL_URL` | دامنه‌ی پنل |
| `NODE_TOKEN` | همان توکن لوکیشن Cloudflare |
| `WS_PATH` | `/ws` |
| `PROXYIP` | (اختیاری) آدرس پروکسی برای مقاصدی که CF مستقیم نمی‌تواند باز کند |

4. ذخیره و Deploy کن؛ دامنه‌ی `*.workers.dev` را در لوکیشن پنل بگذار.
5. در پنل، ترافیک و کاربران این لوکیشن هم مثل بقیه شمرده می‌شود.

---

## ۶) نود روی VPS خودت (اختیاری)

اگر سرور شخصی داری، همان سرویس نود را روی آن اجرا کن:

```bash
git clone <your-fork-url> mlp && cd mlp
sudo bash node/install-vps.sh
```

اسکریپت از تو `MLP_PANEL_URL` و `MLP_NODE_TOKEN` را می‌پرسد، سرویس `systemd` می‌سازد و روی پورت انتخابی گوش می‌دهد.
اگر روی سرور پورت ۸۰/۴۴۳ آزاد نیست، پورت دیگری بده و در پنل ذخیره کن:
- برای ترابرد **TCP**: در پنل «پورت TCP» را همان پورت بگذار و ترابرد TCP را تیک بزن (توجه: VLESS بدون TLS قابل شناسایی است؛ برای استفاده‌ی جدی TLS/Reality را جدا راه‌اندازی کن).
- برای **WS/XHTTP**: نیاز به یک reverse proxy با TLS داری (Caddy/Nginx) که به پورت نود پروکسی کند.

## ۷) ربات تلگرام

1. تب **تنظیمات** → توکن ربات را بگذار، آیدی‌های عددی ادمین‌ها را با کاما بنویس → ذخیره.
2. وضعیت ربات را **روشن** کن و «تست ربات» را بزن.
3. در تب **پلن‌ها** پلن بساز (نام، حجم، مدت، قیمت، سرعت، حداکثر IP).
4. حالا مشتری با `/start` وارد می‌شود → `پلن‌ها` → انتخاب پلن → ارسال عکس رسید → ادمین دکمه‌ی «تأیید» را می‌زند → لینک ساب خودکار برای مشتری ارسال می‌شود.

دستورات ادمین: `/stats`، `/nodes`، `/adduser <name> <gb> <days>`، `/broadcast` از پنل.

---

## ۸) بروزرسانی و پشتیبان‌گیری

- **آپدیت کد**: در GitHub روی Fork یک `Sync fork` بزن (یا تغییرات را بکش)؛ Railway خودش دوباره Deploy می‌کند.
- **پشتیبان**: فایل `/data/mlp.sqlite3` روی Volume است. با `railway run` یا از داخل کانتینر کپی بگیر:

```bash
# داخل کانتینر پنل
sqlite3 /data/mlp.sqlite3 ".backup '/data/backup-$(date +%F).sqlite3'"
```

## ۹) عیب‌یابی سریع

| مشکل | راه‌حل |
|---|---|
| لوکیشن آفلاین می‌ماند | `https://<node>/healthz` را ببین؛ `panel_error` علت را می‌گوید. معمولاً `MLP_PANEL_URL` یا `MLP_NODE_TOKEN` غلط است. |
| صفحه‌ی ساب باز می‌شود ولی کلاینت وصل نمی‌شود | در پنل مسیرها (`/ws` یا `/xhttp`) باید با متغیرهای نود یکی باشد. `https://<node>/ws` باید خطای ۴۰۰ بدهد (یعنی مسیر زنده است). |
| مصرف ثبت نمی‌شود | فاصله‌ی گزارش ۱۵ ثانیه است؛ چند لحظه صبر کن. لاگ نود را ببین. |
| پنل بعد از دیپلوی خالی شد | Volume روی `/data` وصل نبوده. |
| ربات پیام نمی‌دهد | توکن/آیدی ادمین را بررسی و «تست ربات» را بزن؛ Webhook قبلی هم پاک می‌شود. |
| سرعت کم است | ترابرد `XHTTP` را امتحان کن یا لوکیشن نزدیک‌تر بگیر؛ محدودیت سرعت کاربر را هم چک کن. |

---

## ۱۰) نکات امنیتی

- رمز پیش‌فرض `admin` را فوراً عوض کن (تنظیمات → رمز عبور).
- توکن نود فقط اجازه‌ی «گرفتن لیست کاربران» و «گزارش مصرف» دارد؛ اگر لو رفت، از دکمه‌ی **توکن جدید** استفاده کن.
- پنل را بدون رمز قوی روی دامنه‌ی عمومی نگذار (پنل API ادمین دارد).
- برای لوکیشن‌های حساس، ترافیک را از Cloudflare عبور بده و `PROXYIP` را تنظیم کن.
