# همه‌ی لوکیشن‌ها: مسیر خروج (Direct / Proxy IP / Tunnel) 🌐

سؤال: «چطور بدون سرور جدید، لوکیشن‌های بیشتر بسازم یا IP خروجی را عوض کنم؟»
جواب: هر لوکیشن یک **مسیر خروج (Egress)** دارد. خودِ نود همیشه یکی است، ولی تعیین می‌کنی از
کجا به اینترنت وصل شود:

| حالت | معنی | مناسب برای |
|---|---|---|
| `direct` | خود نود خروجی است | سرویس Railway/VPS در ریجن دلخواه |
| `proxy` | از **پروکسی IP** (SOCKS5 / SOCKS5h / HTTP CONNECT) رد می‌شود | عوض کردن IP خروجی، چند لوکیشن روی یک سرور |
| `chain` | **تانل** به یک سرور VLESS دیگر (نود خودت، ورکر، هر سرور VLESS) | ترکیب دو لوکیشن، عبور از شبکه‌ی سخت، IP خروجی متفاوت |
| `auto` | اول خروجی تنظیم‌شده، اگر خراب شد مسیر سالم بعدی (و در نهایت خودِ نود) | پایداری حداکثری |

همه‌ی این‌ها **از داخل پنل** (فرم لوکیشن → بخش «مسیر خروج») قابل تنظیم است و **زنده** روی نود
اعمال می‌شود: نود با هر `sync` پیکربندی تازه را می‌گیرد؛ نیازی به ری‌استارت یا تغییر Variables نیست.
(اگر در پنل چیزی تنظیم نکنی، مقدارهای `MLP_*` خود سرویس نود معتبر است.)

---

## ۱. پروکسی IP (SOCKS5 / HTTP)

در فرم لوکیشن:

```text
حالت: پروکسی IP
فهرست پروکسی‌ها:
  1.2.3.4:1080
  user:pass@5.6.7.8:1080
  http://9.9.9.9:8080
نوع پیش‌فرض: socks5h (DNS روی پروکسی) | socks5 (DNS محلی) | http
انتخاب بین چند پروکسی: fastest | roundrobin | random
```

- `socks5h` یعنی نام دامنه به پروکسی سپرده می‌شود (برای دور زدن DNS داخلی بهتر است).
- چند پروکسی بدهی، سالم‌ترین/سریع‌ترین انتخاب می‌شود و در خرابی، مسیر بعدی جایگزین می‌شود.
- هر مسیر آمار خودش را دارد: تأخیر (EWMA)، تعداد موفق/ناموفق، خنک‌سازی ۶۰ ثانیه‌ای بعد از خطا.

معادل متغیرهای محیطی روی سرویس نود:

```env
MLP_EGRESS=proxy
MLP_PROXY_LIST=1.2.3.4:1080|user:pass@5.6.7.8:1080
MLP_PROXY_TYPE=socks5h
MLP_PROXY_ROTATE=fastest
# یا ساده‌تر، یک پروکسی:
MLP_PROXY_IP=1.2.3.4
MLP_PROXY_PORT=1080
MLP_PROXY_USER=user
MLP_PROXY_PASS=pass
```

نکته: UDP در حالت پروکسی از خود نود خارج می‌شود (UDP روی SOCKS5 پشتیبانی نمی‌شود).
اگر فقط TCP می‌خواهی، هیچ تنظیم اضافه‌ای لازم نیست؛ کلاینت‌ها به‌صورت پیش‌فرض TCP می‌فرستند.

## ۲. تانل / چین به نود دیگر

دو حالت رایج:

### الف) همه‌ی کاربران یک نود از نود دیگر خروج بگیرند

```text
حالت: تانل/چین
هاست سرور بالادستی: node-eu.up.railway.app
پورت: 443
مسیر: /ws
UUID:  ← یک کاربر روی نود بالادستی بساز و UUID او را بگذار
TLS: ✅ (wss)      SNI: خالی یا دامنه‌ی خودت
```

فلوی کار:

1. روی **نود بالادستی** یک کاربر بساز (تب کاربران) — این کاربر «حامل تانل» است.
2. کاملاً معمولی لینکش را به هیچ‌کس نده؛ فقط UUID را در لوکیشن دیگر بگذار.
3. لوکیشن دوم را با `chain` به آن UUID وصل کن. از این لحظه ترافیک مشتریانِ لوکیشن دوم
   از نود اول بیرون می‌رود (IP خروجی = نود اول) و همه‌ی محدودیت‌های حجم/انقضا سر جای خودشان است.

مناسب برای:
- پنهان‌کردن IP خروجی سرور اصلی
- اتصال دو ریجن (مثلاً ورودی در آلمان، خروجی در هلند)
- وقتی یک ریجن فیلتر است و ریجن دیگر نه

### ب) زنجیره‌ی چندمرحله‌ای با ورکر Cloudflare

ورکر Cloudflare را می‌توانی به‌عنوان «سرور بالادستی» بگذاری:

```env
CHAIN_URL=wss://my-worker.workers.dev/ws
CHAIN_UUID=UUID-کاربر-روی-نود-اصلی
```

یعنی ورکر → نود اصلی → اینترنت. `worker.js` همین را پشتیبانی می‌کند.

## ۳. ورکر Cloudflare: پروکسی IP و تانل

| متغیر | کار |
|---|---|
| `PROXYIP` | آدرس پروکسی IP (مثلاً `1.2.3.4` یا `1.2.3.4:443`) |
| `PROXYIP_UUID` | اگر پروکسی IP یک سرور VLESS است، UUID آن؛ ورکر قبل از داده، هدر VLESS مقصد را می‌فرستد |
| `CHAIN_URL` + `CHAIN_UUID` | تانل به یک سرور VLESS/WS (نود خودت) |
| `PANEL_URL` + `NODE_TOKEN` | اتصال ورکر به پنل (همان API نودها) |

سه ترکیب پرکاربرد:

1. **ورکر مستقیم** → لوکیشن «☁️ Cloudflare» با IP خروجی متغیر.
2. **ورکر + پروکسی IP** → خروجی ثابت روی سروری که خودت داری.
3. **ورکر + تانل به نود** → مشتری به لبه‌های Cloudflare وصل می‌شود و ترافیک از نود تو بیرون می‌رود
   (مقاوم‌ترین حالت در برابر فیلترینگ).

و برعکسش هم برقرار است: **نود خودت می‌تواند پروکسی IP ورکر باشد** — `MLP_TCP_PORT` را ست کن
(روی Railway با یک TCP Proxy). ورکر با `PROXYIP=<host>` و `PROXYIP_UUID=<uuid یک کاربر>` به آن وصل می‌شود.
همین پورت، ترابرد TCP خام را هم برای کلاینت‌ها سرو می‌کند.

## ۴. ترابردها

| ترابرد | پیش‌فرض | فعال‌سازی |
|---|---|---|
| **WS** | ✅ `/ws` | — |
| **XHTTP** | ✅ `/xhttp` | — |
| **TCP** | ❌ | `MLP_TCP_PORT=<port>` روی نود (روی Railway: TCP Proxy) |
| **Xray (WS/XHTTP/TCP)** | با `MLP_ENGINE=xray` | `node/Dockerfile.xray` |

در پنل، برای هر لوکیشن تیک ترابردها را بزن؛ کانفیگ‌ها خودکار در ساب مشتری می‌آیند.

## ۵. تست و عیب‌یابی

در پنل → تب لوکیشن‌ها → دکمه‌ی **«تست خروج»**: از خود نود می‌خواهد همه‌ی مسیرها را امتحان کند و
تأخیر/خطای هرکدام را نشان می‌دهد. معادل دستی:

```bash
curl "https://<node>/egress?key=<MLP_NODE_TOKEN>"          # وضعیت لحظه‌ای مسیرها
curl "https://<node>/egress?key=<MLP_NODE_TOKEN>&test=1"    # تست واقعی همه‌ی مسیرها
```

| نشانه | راه‌حل |
|---|---|
| همه چیز `direct` مانده | در پنل مسیر خروج تنظیم نشده و env سرویس نود هم خالی است |
| پروکسی `ECONNREFUSED` | آدرس/پورت پروکسی غلط یا پروکسی IP خاموش است |
| SOCKS5: «روش احراز قبول نشد» | `MLP_PROXY_TYPE=socks5h` را با `user:pass@host:port` امتحان کن |
| تانل وصل نمی‌شود | UUID روی سرور بالادستی معتبر نیست، یا مسیر WS اشتباه است (`/ws`) |
| تانل با خطای گواهی | `SNI` درست را بگذار یا «نادیده گرفتن خطای گواهی» را تیک بزن |
| بعد از خطا، وصل می‌شود ولی IP عوض نمی‌شود | حالت `auto` با fallback فعال است؛ اگر نمی‌خواهی، تیک fallback را بردار |
| می‌خواهی مطمئن شوی IP خروجی عوض شده | در سایت `ifconfig.me` از داخل تونل تست کن یا از `/egress` تأخیرها را ببین |

## ۶. سناریوهای آماده

| می‌خواهم… | راه |
|---|---|
| ۵ لوکیشن با IP‌های مختلف از یک سرور | یک سرویس نود + ۵ لوکیشن که هرکدام یک `proxy` (پروکسی IP کشور خودش) دارند |
| ترافیک مشتری از سرور دوم بیرون برود | لوکیشن دوم با `chain` به UUID یک کاربر روی نود اول |
| حداقل هزینه، بیشترین مقاومت | ورکر Cloudflare + تانل به نود Railway (`CHAIN_URL`) |
| ترابرد TCP در کنار WS | `MLP_TCP_PORT` روی نود و تیک TCP در لوکیشن |
| پایداری حتی وقتی پروکسی می‌افتد | حالت `auto` + تیک fallback (مسیر جایگزین و در نهایت خود نود) |
